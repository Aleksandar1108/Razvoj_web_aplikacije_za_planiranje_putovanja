================================================================================
3. KOMPONENTE — GORNJI SLOJ
================================================================================

[Frontend React]
  Tehnologija: React + TypeScript + Vite
  Lokacija u kodu: folder client/
  Struktura: pages/, components/, services/, models/, context/AuthContext
  HTTP: sve pozive radi kroz servise (authService, travelPlansService, …), NE direktno
         iz komponenti; zajednički httpClient.ts koristi fetch()
  Konfiguracija URL-ova: .env (VITE_* promenljive) → client/src/config/env.ts

  Servisi koje frontend gađa (iz .env.example):
    VITE_API_BASE_URL              → Web1           port 8915
    VITE_TRAVEL_PLANS_API_BASE_URL   → TravelPlansApi port 8916
    VITE_DESTINATIONS_API_BASE_URL   → DestinationsApi port 8917
    VITE_ACTIVITIES_API_BASE_URL     → ActivitiesApi  port 8919
    VITE_EXPENSES_API_BASE_URL       → ExpensesApi    port 8920
    VITE_CHECKLIST_API_BASE_URL      → ChecklistApi   port 8921
    VITE_SHARING_API_BASE_URL        → SharingApi     port 8922

  Autentikacija na klijentu:
    - JWT access token u localStorage
    - Header: Authorization: Bearer <token>
    - Za deljene planove dodatno: X-Share-Token: <token iz QR>

  Povezati strelicama (plava puna) sa SVAKIM mikroservisom koje koristi — nije jedan
  centralni backend, već više paralelnih REST poziva.

4. KOMPONENTE — SREDNJI SLOJ (Service Fabric aplikacija)
================================================================================

Okvir: "PlaniranjePutovanja" (ApplicationTypeName u ApplicationManifest.xml)
Svi servisi su: StatelessService (StatelessServiceType u ServiceManifest.xml)

----------------------------------------------------------------------
4.1 Web1 (glavni API — autentikacija, admin korisnika, obaveštenja)
----------------------------------------------------------------------
  Tip: Stateless Service Fabric servis
  Port: 8915 (ServiceEndpoint u Web1/PackageRoot/ServiceManifest.xml)
  Uloga: Autentikacija, upravljanje korisnicima (admin), in-app obaveštenja

  Kontroleri / REST resursi:
    POST   /api/v1/auth/register
    POST   /api/v1/auth/login        → vraća JWT
    GET    /api/v1/auth/me           → validacija tokena
    GET    /api/v1/admin/stats
    GET    /api/v1/admin/users
    PATCH  /api/v1/admin/users/{id}
    GET    /api/v1/notifications
    GET    /api/v1/notifications/unread-count
    PATCH  /api/v1/notifications/{id}/read
    PATCH  /api/v1/notifications/read-all
    GET    /api/v1/health
    GET    /api/v1/health/db

  Poslovna logika:
    - AuthService: registracija, login, BCrypt heš lozinki
    - AdminService: pregled/izmena korisnika i uloga
    - NotificationService: čitanje/označavanje obaveštenja

  Tabele u bazi (primarni vlasnik):
    Roles, Users, RefreshTokens, UserNotifications

  Strelica ka SQL: zelena puna

----------------------------------------------------------------------
4.2 TravelPlansApi (planovi putovanja)
----------------------------------------------------------------------
  Port: 8916
  Uloga: CRUD planova putovanja; admin kreira plan za izabranog korisnika

  REST:
    GET/POST        /api/v1/travel-plans
    GET/PUT/DELETE  /api/v1/travel-plans/{id}
    GET             /api/v1/admin/travel-plans        (samo Admin)
    POST            /api/v1/admin/travel-plans        (admin kreira plan za userId)

  Tabele: TravelPlans (primarno)
  Čita i: Users (join za admin listu), TravelPlanShareLinks/Recipients (pristup),
           UserNotifications (admin obaveštenja)

  Validacija u servisu:
    - krajnji datum >= početni
    - budžet >= 0

----------------------------------------------------------------------
4.3 DestinationsApi (destinacije po planu)
----------------------------------------------------------------------
  Port: 8917
  Uloga: CRUD destinacija unutar plana; admin pregled svih destinacija

  REST:
    GET/POST        /api/v1/travel-plans/{travelPlanId}/destinations
    GET/PUT/DELETE  /api/v1/travel-plans/{travelPlanId}/destinations/{id}
    GET             /api/v1/admin/destinations   (Admin)

  Tabele: TravelDestinations (primarno)
  Čita: TravelPlans (validacija datuma destinacije unutar datuma plana)

  Pristup: TravelPlanAccessGuard (vlasnik / share view|edit / admin)

----------------------------------------------------------------------
4.4 ActivitiesApi (aktivnosti po danima)
----------------------------------------------------------------------
  Port: 8919
  Uloga: CRUD aktivnosti (kalendar) za plan

  REST:
    /api/v1/travel-plans/{travelPlanId}/activities
    /api/v1/travel-plans/{travelPlanId}/activities/{id}

  Tabele: TravelActivities
  Validacija: datum aktivnosti unutar plana; status enum; procenjeni trošak >= 0

----------------------------------------------------------------------
4.5 ExpensesApi (troškovi i budžet)
----------------------------------------------------------------------
  Port: 8920
  Uloga: CRUD troškova; pregled sumarnog budžeta (plan + aktivnosti + troškovi)

  REST:
    /api/v1/travel-plans/{travelPlanId}/expenses
    /api/v1/travel-plans/{travelPlanId}/expenses/summary
    /api/v1/travel-plans/{travelPlanId}/expenses/{id}

  Tabele: TravelExpenses (primarno)
  Čita: TravelPlans, TravelActivities (za summary)

----------------------------------------------------------------------
4.6 ChecklistApi (packing lista)
----------------------------------------------------------------------
  Port: 8921
  Uloga: CRUD stavki checkliste; toggle "završeno"

  REST:
    /api/v1/travel-plans/{travelPlanId}/checklist-items
    /api/v1/travel-plans/{travelPlanId}/checklist-items/{id}
    (toggle završeno — odgovarajući PUT/PATCH endpoint u kontroleru)

  Tabele: TravelChecklistItems

----------------------------------------------------------------------
4.7 SharingApi (deljenje planova — QR / link)
----------------------------------------------------------------------
  Port: 8922
  Uloga: Generisanje share linka; claim QR-a; lista planova deljenih sa mnom

  REST:
    POST /api/v1/travel-plans/{travelPlanId}/share-links
    GET  /api/v1/shared-plans
    POST /api/v1/share-links/claim

  Tabele: TravelPlanShareLinks, TravelPlanShareRecipients
  Dozvole: view | edit (čuva se u bazi; backend proverava na svakom zahtevu)

----------------------------------------------------------------------
ZAJEDNIČKO SVIM DOMENSKIM API-ima (2–7)
----------------------------------------------------------------------
  - ASP.NET Core Web API na Kestrel unutar SF StatelessService
  - JWT Bearer autentikacija (isti Issuer/Audience/SigningKey kao Web1)
  - TravelPlanAccessGuard: Owner | ShareView | ShareEdit | Admin | X-Share-Token
  - AdminPlanNotificationService: pri admin izmeni upis u UserNotifications (sync)
  - DTO ↔ Entity mapiranje u Service sloju (npr. Map(entity))
  - NEMA poziva drugim mikroservisima preko HTTP-a ili Remoting-a

    Deljenje:
      - TravelPlanShareLinks     (FK → TravelPlans ON DELETE CASCADE)
      - TravelPlanShareRecipients (FK → TravelPlans ON DELETE CASCADE)

    Obaveštenja:
      - UserNotifications        (FK → Users ON DELETE CASCADE; TravelPlanId opciono)

  Od svakog mikroservisa (2–7 + Web1): ZELENA PUNA LINIJA ka ovom cilindru
  Napomena na dijagramu: "Deljena baza — svaki servis ima svoj DbContext i svoje tabele"


================================================================================
6. BEZBEDNOST (kutija ili fusnota)
================================================================================

  - Registracija/Prijava → Web1 → BCrypt PasswordHash u Users
  - Login → JWT (potpis, issuer, audience, istek) — ValidateLifetime + SigningKey
    na Web1 i svim mikroservisima
  - Uloge: User (1), Admin (2) — [Authorize(Roles = "Admin")] na admin endpointima
  - Deljeni pristup bez naloga vlasnika: X-Share-Token header + hash u bazi


================================================================================
7. TOKOVI ZA NUMERISANE STRELICE (kao "Tok kupovine" u primeru)
================================================================================

TOK 1 — Registracija i prijava
  1. Korisnik → React (Login/Register forma)
  2. React → Web1: POST /api/v1/auth/login ili /register  [HTTP plava]
  3. Web1 → SQL: Users, Roles  [zelena]
  4. Web1 → React: JWT access token
  5. React čuva token; sledeći pozivi šalju Authorization: Bearer

TOK 2 — Kreiranje plana putovanja (običan korisnik)
  1. React → TravelPlansApi: POST /api/v1/travel-plans + JWT  [plava]
  2. TravelPlansApi → SQL: INSERT TravelPlans (UserId iz JWT)  [zelena]
  3. Odgovor sa planId → React navigira na detalje plana

TOK 3 — Dodavanje destinacije, aktivnosti, troška, checkliste
  1. React → odgovarajući API (Destinations / Activities / Expenses / Checklist)
     PUT/POST pod /api/v1/travel-plans/{id}/...
  2. API: TravelPlanAccessGuard proverava vlasništvo ili share edit ili admin
  3. API → SQL: INSERT/UPDATE u odgovarajućoj tabeli
  4. Validacija datuma i iznosa u Service sloju

TOK 4 — Deljenje plana (QR)
  1. Vlasnik → React → SharingApi: POST .../share-links (permission view|edit)
  2. SharingApi → SQL: TravelPlanShareLinks (token hash)
  3. QR kod sadrži token / link
  4. Drugi korisnik → React: POST /api/v1/share-links/claim
  5. SharingApi → SQL: TravelPlanShareRecipients
  6. React → GET /api/v1/shared-plans (lista deljenih planova)

TOK 5 — Admin menja tuđi plan
  1. Admin → React (uloga Admin u JWT)
  2. React → bilo koji domenski API (npr. PUT travel-plans/{id} ili destinacije…)
  3. TravelPlanAccessGuard → Admin pristup
  4. Izmena u SQL
  5. AdminPlanNotificationService → SQL: INSERT UserNotifications za vlasnika plana
  6. Vlasnik → React → Web1 GET /notifications (zvonce u headeru)

TOK 6 — Admin kreira plan za korisnika
  1. Admin → React → TravelPlansApi: POST /api/v1/admin/travel-plans
     (body: ownerUserId + podaci plana)
  2. TravelPlansApi → SQL: TravelPlans za izabranog UserId
  3. Opciono obaveštenje vlasniku (ako admin ≠ vlasnik)

9. TEKST ZA KUTIJU "VAŽNE NAPOMENE" (dno dijagrama)
================================================================================

  - Svi mikroservisi su STATELESS; perzistencija isključivo u SQL Serveru.
  - Nema Service Fabric Remoting — komunikacija Frontend ↔ API isključivo HTTP/REST.
  - Nema Reliable Queue / asinhronog dispatcher-a; obaveštenja se upisuju odmah u bazu.
  - Jedna baza PlaniranjePutovanja; logička podela po tabelama i mikroservisima.
  - Brisanje TravelPlans kaskadno briše destinacije, aktivnosti, troškove, checklistu,
    share linkove (ON DELETE CASCADE u SQL migracijama).
  - REST konvencija: api/v1/, množina, kebab-case (travel-plans, checklist-items).
  - Migracije baze: Database/Migrations/000–012 (.sql skripte).
